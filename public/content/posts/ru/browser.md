# Браузер

## После ввода URL в адресную строку

1. Браузер через [DNS](/posts/network#DNS) получает IP-адрес домена.
2. Устанавливается [TCP](/posts/network#TCP)-соединение, при HTTPS происходит [TLS](/posts/network#TLS)-рукопожатие.
3. Отправляется HTTP-запрос, приходит HTML-ответ.
4. HTML парсится в DOM, по ходу находятся ссылки на CSS/JS/картинки.
5. CSS парсится в CSSOM, формируется render tree (DOM + CSSOM).
6. Layout рассчитывает геометрию, затем paint рисует пиксели, composite собирает слои.
7. JS подключает интерактивность (особенно важно для SPA/SSR-гидратации).

## Critical Rendering Path (CRP)

CRP — это цепочка шагов от получения HTML до первого рендера страницы. Ключевые этапы:

- DOM → CSSOM → render tree → layout → paint → compositing.

### Что может блокировать рендер

- **CSS** — рендер-блокирующий: пока не построен CSSOM, отрисовка не начнётся.
- **Скрипты без `defer/async`** — блокируют парсинг HTML и могут задерживать рендер.
- **Шрифты** — могут задерживать отрисовку текста (FOIT/FOUT).

### Как ускоряют

- Добавляют `defer` для скриптов, критичные — оставляют синхронными.
- Выносят «critical CSS» в `<style>` и откладывают остальное.
- Используют `preload`/`preconnect` для критических ресурсов.
